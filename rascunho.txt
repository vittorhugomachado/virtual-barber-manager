⚙️ Edge Functions (repo das functions)
Arquivo	Papel no fluxo
create-subscription/index.ts	Porta de criação. Converte trial → pago: autentica, valida dono, lê plano do banco, rate limit, claim, cria/reusa customer+subscription no Asaas, grava IDs (incomplete), busca a fatura.
asaas-webhook/index.ts	Sincroniza o estado. Recebe eventos do Asaas, valida token, dedup, acha a assinatura, espelha o pagamento e seta active/past_due + current_period_end.
reconcile-subscriptions/index.ts	Rede de segurança (cron). Reprocessa eventos que ficaram presos no webhook.
_shared/asaas.ts	Client HTTP do Asaas (createCustomer, createSubscription, lookups, listSubscriptionPayments) com timeout/guarda da key.
_shared/supabaseAdmin.ts	Client service_role (usado pela create-subscription).

2) O fluxo em texto comum
🌱 Nascimento (signup)
Dono se cadastra → trigger do banco cria a barbershops + a subscriptions com status = trialing (30 dias) → ainda sem IDs do Asaas.

💳 Converter trial em pago (/assinar)
Front abre /assinar → buy-plan-page chama getMySubscription().
→ Se já tem asaas_subscription_id → redireciona para /minha-assinatura.
→ Senão, mostra o wizard.
Passo 1: BuyPlanMain chama getPlans() → mostra os 3 cards (preços do banco). Cliente escolhe um → passo 2.
Passo 2: escolhe método (Pix/Boleto/Cartão) + digita CPF/CNPJ (validado no front).
Front chama create-subscription (via supabase.functions.invoke).
🔒 Dentro da create-subscription
Ela verifica, em ordem:

JWT válido? (quem é o usuário) → senão 401.
CPF/CNPJ válido? (M4) → senão 400.
Rate limit ok? (rate_limit_hit, M5) → senão 429.
É dono da barbearia? → senão 403.
Plano existe e está ativo? (lê preço/ciclo do banco, nunca do front).
Já tem asaas_subscription_id? → senão 409 (vai pra /minha-assinatura).
Claim atômico (claim_subscription_provisioning, H2) → se outro request está criando, 409.
Customer no Asaas: procura por externalReference (H3) → reusa ou cria.
Subscription no Asaas: procura por externalReference (H3) → reusa ou cria.
Grava asaas_customer_id/asaas_subscription_id + status = incomplete (libera o claim).
Busca a 1ª fatura (invoiceUrl) → devolve para o front.
→ Front recebe invoice_url → botão "Ir para o pagamento" abre a página hospedada do Asaas.

💰 Pagamento
Cliente paga no Asaas (Pix/Boleto/Cartão — cartão digitado lá, nunca no nosso app).

📨 Webhook (asaas-webhook)
Asaas dispara o evento → webhook verifica:

Token confere? (constant-time, M2) → senão 401.
Já processei esse evento? (dedup por processed_at, C2) → se sim, ignora.
Acho a subscription pelo asaas_subscription_id?
→ Não: retry (500) até 5x; esgotou → gave_up + alerta na ops_alerts.
→ Sim: espelha o pagamento em payments e:
Evento de pagamento confirmado → status = active + current_period_end = max(fim atual, paymentDate) + ciclo (H1).
Evento de falha/vencimento → status = past_due + alerta.
🛟 Rede de segurança (reconcile-subscriptions, cron 10 min)
Pega eventos presos/gave_up → reprocessa (reaplica o efeito). Garante que nada fique perdido.

🚪 O acesso (gate)
Quando a barbearia tenta criar registros (membros, futuramente clientes/agendamentos):
→ chama is_barbershop_active() → lê current_period_end (+ carência) →

dentro do prazo → libera o INSERT.
fora do prazo → bloqueia (somente leitura).
Resumo de 1 linha do "caminho feliz"
Signup cria o trial → /assinar mostra os planos (do banco) → create-subscription valida tudo e cria a assinatura no Asaas (incomplete) → cliente paga no Asaas → asaas-webhook confirma e seta active + current_period_end → gate lê esse campo e libera o uso. Se o webhook falhar, a reconciliação conserta.
